# Development

Use this page to set up the toolchain, run the checks CI runs, regenerate the
committed schemas and fixtures, and build with Nix.

## Toolchain

| Tool | Version | Source |
| --- | --- | --- |
| Rust | 1.99.1 | `rust-toolchain.toml`, `dtolnay/rust-toolchain@1.99.1` in CI |
| rustfmt, clippy | 1.99.1 components | `rust-toolchain.toml` |
| cargo | 1.99.x | Rust toolchain; the Nix devShell follows nixpkgs |
| actionlint, shellcheck | latest from nixpkgs | actionlint workflow |

The workspace uses edition 2024 and resolver 3. The root `Cargo.toml` pins
every third-party dependency, and `Cargo.lock` is committed. Do not add a crate
without agreement: a new dependency changes the supply-chain story in
[security](security.md) and the license allow-list in `deny.toml`.

## Environment

With rustup installed, `rust-toolchain.toml` selects 1.99.1 automatically:

```sh
cargo build --workspace
cargo test --workspace --all-features
```

The Nix flake provides the same tools without rustup:

```sh
nix develop
cargo --version
```

`.envrc` contains `use flake`, so direnv enters the same shell automatically.

### Sandboxed or unprivileged environments

Some agent sandboxes mount the home directory read-only. If `~/.cargo` or
`~/.cache` is read-only, keep the caches inside the checkout:

```sh
export CARGO_HOME="$PWD/.cargo-home"     # cargo registry and build cache
export XDG_CACHE_HOME="$PWD/.cache-nix"  # nix fetcher cache
```

Both directories are gitignored. Nix writes build results to the Nix store
through the daemon; only the fetcher and eval caches need to be writable.

## Checks

Run what CI runs:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
bash scripts/fetch-fixtures.sh
cargo test --workspace --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
```

On a passing tree, every command exits 0.

`scripts/fetch-fixtures.sh` downloads the two real GGUF files into
`fixtures/real/` (gitignored) and verifies their SHA-256. Tests that need them
skip with a notice when the files are absent, so a clean checkout can test the
rest without network access. See [fixtures](../fixtures/README.md).

The actionlint workflow shellchecks `scripts/*.sh`, and `rust-toolchain.toml`
pins the Rust and cargo versions the commands run under. See
[testing](testing.md) for the test layout.

## Schemas

`schemas/*.json` are generated from Rust types and committed. A test fails when
a committed schema is stale. Regenerate after changing the types:

```sh
UPDATE_SCHEMAS=1 CARGO_HOME="$PWD/.cargo-home" cargo test -p hoard-core --test schema
UPDATE_SCHEMAS=1 CARGO_HOME="$PWD/.cargo-home" cargo test -p hoard-gguf --lib schema
```

Then run the full suite (without `UPDATE_SCHEMAS`) and commit the changed
schema files with the type change. [`docs/inspect.md`](inspect.md) and
[`docs/manifest.md`](manifest.md) describe the contracts the schemas encode.

## Synthetic fixtures

The committed GGUF fixtures under `crates/hoard-gguf/tests/fixtures/` are
generated by the `fixture` module and checked in so tests are deterministic:

```sh
UPDATE_FIXTURES=1 CARGO_HOME="$PWD/.cargo-home" \
  cargo test -p hoard-gguf --features testing --test generate
```

Do not edit GGUF fixtures or their golden JSON by hand; edit the fixture
builder and regenerate. Real model files are never committed.

## Nix

```sh
nix flake show --all-systems   # evaluate every output without building
nix develop --command cargo --version
nix flake check                # builds the package check
nix build .#default            # builds both binaries
nix run .# -- --version
nix fmt                        # nixfmt
```

The flake exposes three systems: `x86_64-linux`, `aarch64-linux`, and
`aarch64-darwin`. nixpkgs 26.11 dropped `x86_64-darwin`, so Intel macOS has no
devShell or package output. Cargo builds may still work there with a
system-provided Rust, but the flake does not guarantee it. The supported systems
are also listed in [limits and non-goals](limitations.md).

`nixpkgs` is an input without `flake-utils` or devenv: the three systems are
enumerated by hand. `flake.lock` pins a nixos-unstable revision. Updating it
resolves the branch through the GitHub API, which is rate-limited in some
sandboxes; if resolution fails, pin a full commit rev in `flake.nix` and re-run
`nix flake lock`.

The Nix package builds the whole workspace with `rustPlatform.buildRustPackage`
and installs both `hoard` and `hoard-gguf`. Dependencies come from the committed
`Cargo.lock` via `cargoLock.lockFile` (`importCargoLock`), so the build needs no
aggregate vendoring hash: each crate is fetched by its locked checksum and the
build itself runs offline. To advance dependencies, update `Cargo.lock`, commit
it, and re-run `nix build .#default`.

Tests that need `fixtures/real/` skip inside the Nix sandbox because those
files are not part of the flake source; a Nix build therefore does not download
the real corpus.

## CI

| Workflow | What it runs |
| --- | --- |
| `.github/workflows/ci.yml` | fmt, clippy (`-D warnings`), fixture download, workspace tests, `cargo doc` with `-D warnings`. |
| `.github/workflows/nix.yml` | `nix flake check`, `nix build .#default`, `--version` smoke checks, real-fixture inspect smoke test. |
| `.github/workflows/deny.yml` | `cargo-deny check` over advisories, bans, licenses, and sources. |
| `.github/workflows/actionlint.yml` | actionlint on workflows and shellcheck on `scripts/*.sh`. |

All workflows run on `ubuntu-24.04`, on pushes to `main`, on pull requests, and
on demand. `ci.yml` pins Rust to 1.99.1 with rustfmt and clippy.

| `.github/workflows/` | CI. |
| `flake.nix`, `flake.lock` | Dev shell, package, apps, checks, formatter. |

## Versioning

The workspace version lives in `[workspace.package].version` in the root
`Cargo.toml`; `flake.nix` reads it from there. A release updates `Cargo.toml`,
`Cargo.lock`, and `CHANGELOG.md` together, then tags `v<version>`. The binary
`--version` output comes from Cargo's package version.
